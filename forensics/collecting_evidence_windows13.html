Case File // 013

COLLECTING EVIDENCE IN WINDOWS USING LINUX

A practical guide to safely acquiring, preserving, and analyzing Windows digital evidence from a Linux forensic environment

PREPARATION

HAVE A CLEAR INCIDENT RESPONSE PLAN.

BOOTING THE TARGET MACHINE

USE LIVE BOOTABLE USB (LIKE: KALI LINUX, ARCH)

DATA ACQUISITION

DISK IMAGING
CREATE A BIT-BY-BIT COPY OF THE WINDOWS HARD DRIVE.
TOOLS
dd if=/dev/sda of=win.dd bs=4M
— or —
dc3dd if=/dev/sda of=win.dd
— or —
dcfldd if=/dev/sda of=win.dd hash=md5,sha256 hashlog=hash.txt
USE DC3DD FOR FASTLY CREATE DISK IMAGE USE DCFLDD - IT IS AN ENHANCED VERSION OF DD
NETWORK DATA CAPTURE
tcpdump -i wlan0 -w net.pcap
IF THE SYSTEM IS LIVE, CAPTURE NETWORK TRAFFIC USING TCPDUMP OR WIRESHARK.

EVIDENCE PRESERVATION

USE HARDWARE OR SOFTWARE WRITE BLOCKERS TO ENSURE NO DATA MODIFICATION ON THE TARGET DRIVE. COMPUTE AND STORE HASH VALUES OF THE ORIGINAL DATA AND THE IMAGE FOR INTEGRITY.
TOOLS
sha256sum drive.dd > out.dd.sha256

DATA ANALYSIS

MOUNTING THE IMAGE
mount -o loop,offset=1228 drive.dd /mnt
MOUNT THE DISK IMAGE FOR ANALYSIS EXAMPLE (offset=1228):
FILE SYSTEM ANALYSIS
fls -r -f ntfs -o1228 win.dd
USE TOOL LIKE 'SLEUTHKIT' TO ANALYZE THE FILE SYSTEM IT SHOWS ALL THE DIRECTORY AND ITS FOLDERS INSIDE WIN.DD
LOG ANALYSIS
pip install --break-system-packages python-evtx
— or —
evtx_dump system.evtx > system.xml
LOGS FILE LOCATION -> windows/system32/winevt/logs/ USEFUL LOG FILES -> system.evtx, application.evtx, security.evtx NOW CONVERT EVTX TO XML
IF IT GIVES ERROR EVTX_DUMP CMD NOT FOUND
/home/whitex/.local/bin/evtx_dump.py sys.evtx > sys.xml
— or —
lnav sys.xml
— or —
pacman -S lnav
