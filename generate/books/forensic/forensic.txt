*VALIDATING THE EVIDENCE
[GENERATE HASHES]
GENERATE CRYPTOGRAPHIC HASH VALUES (EG, MD5, SHA-1, SHA-256) FOR THE ORIGINAL EVIDENCE BEFORE AND AFTER ACQUISITION TO ENSURE DATA INTEGRITY.
[VERIFY HASHES]
COMPARE THE HASH VALUES GENERATED DURING ACQUISITION WITH THOSE GENERATED FROM THE COPIED EVIDENCE TO CONFIRM THAT NO CHANGES HAVE OCCURRED.
[CHAIN OF CUSTODY DOCUMENTATION]
MAINTAIN A DETAILED LOG OF WHO HANDLED THE EVIDENCE, WHEN, AND UNDER WHAT CONDITIONS TO ENSURE THAT THE EVIDENCE HAS NOT BEEN TAMPERED WITH.
[GENERATE HASHES TOOLS]
-md5sum original.dd > o.txt
-md5sum copy.dd > c.txt
-diff o.txt c.txt
[YOU CAN ALSO USE SHA256SUM]
[VERIFY HASH]
-md5sum -c c.txt
[EXAMPLE OF CHAIN OF CUSTODY LOG BOOK]
DATE: 2024-05-25
EVIDENCE ID: IMG001
DESCRIPTION: DISK IMAGE OF SUSPECT'S LAPTOP
ACQUIRED BY: FAIZAN
HASH [MD5]: 9E10709372BB6826BD81
CHAIN OF CUSTODY: TRANSFERRED TO JANE SMITH ON 2024-05-26

*PASSWORD CRACKING - BRUTE FORCE ATTACK
BRUTE FORCE ATTACK INVOLVES SYSTEMATICALLY TRYING ALL POSSIBLE COMBINATIONS OF CHARACTERS UNTIL THE CORRECT PASSWORD IS FOUND.
THIS METHOD GUARANTEES SUCCESS BUT CAN BE TIME CONSUMING, ESPECIALLY FOR COMPLEX PASSWORDS.
[BRUTE FORCE TOOLS]
-zip2john my.zip > hash.txt
-john hash.txt
OR
-fcrackzip -b -c a -l 1-6 my.zip
-hashcat -a3 -m0 hash.txt ?a?a?a?a?a?a
[RUN HASHCAT ON RDP - MD5 MASK EXAMPLE ABOVE]

*PASSWORD CRACKING - DICTIONARY ATTACK
DICTIONARY ATTACKS USE A PREDEFINED LIST OF POSSIBLE PASSWORDS AND TEST EACH ONE.
THIS METHOD IS FASTER THAN BRUTE FORCE BUT ONLY WORKS IF THE PASSWORD IS IN THE DICTIONARY.
[DICTIONARY ATTACK TOOLS]
-john --wordlist=pass hash.txt

*LOGICAL STRUCTURE OF DISK - SECTORS, CLUSTERS, TRACKS
THE LOGICAL STRUCTURE OF A DISK REFERS TO THE WAY DATA IS ORGANIZED AND MANAGED ON THE STORAGE MEDIUM.
[1) SECTORS]
THE SMALLEST UNIT OF DATA STORAGE ON A HARD DISK. TYPICALLY, A SECTOR HOLDS 512 B OF DATA.
[2) CLUSTERS]
A CLUSTER IS A GROUP OF SECTORS. FILE SYSTEM USES CLUSTERS TO MANAGE DATA MORE EFFICIENTLY. FOR EXAMPLE, IF EACH CLUSTER CONTAINS 8 SECTORS, AND EACH SECTOR IS 512 BYTES, THEN EACH CLUSTER HOLDS 4096 BYTES (4KB).
[3) TRACKS]
A TRACK IS A CIRCULAR PATH ON THE SURFACE OF A DISK PLATTER, WHERE DATA IS MAGNETICALLY RECORDED AND READ. EACH TRACK IS DIVIDED INTO SECTORS.
========================================

#
$
*LOGICAL STRUCTURE OF DISK - CYLINDERS, PARTITIONS, FILE SYSTEM, DIRECTORIES
[4) CYLINDERS]
A CYLINDER IS A SET OF TRACKS LOCATED IN THE SAME POSITION ON MULTIPLE PLATTERS WITHIN A HARD DISK.
[5) PARTITIONS]
A PARTITION IS A LOGICAL DIVISION OF A HARD DISK. EACH PARTITION CAN CONTAIN ITS OWN FILE SYSTEM AND OPERATE INDEPENDENTLY.
FOR EXAMPLE: A 1TB HARD DRIVE CAN BE DIVIDED INTO TWO PARTITIONS OF 500 GB EACH.
[6) FILE SYSTEM]
A FILE SYSTEM ORGANIZES AND MANAGES FILES ON A PARTITION. COMMON FILE SYSTEMS INCLUDE NTFS (WINDOWS), HFS+ (MAC) AND EXT4 (LINUX).
[7) DIRECTORIES]
DIRECTORIES ARE ORGANIZATIONAL UNITS WITHIN A FILE SYSTEM THAT CONTAIN FILES AND OTHER DIRECTORIES.
FOR EXAMPLE: IN A LINUX FILE SYSTEM YOU MIGHT HAVE A DIRECTORY STRUCTURE LIKE "/home/user/documents".
========================================

#
$
*LOGICAL STRUCTURE OF DISK - FILES AND HIERARCHY
[8) FILES]
THE ACTUAL DATA STORED ON THE HARD DISK. FILES CAN BE TEXT DOCUMENTS, IMAGES, EXECUTABLES ETC.
[HIERARCHY DIAGRAM]
DISK
- PARTITIONS
  - PRIMARY PARTITION 1
    - FILE SYSTEM
      - DIRECTORIES
        - SUBDIRECTORIES
        - FILES
  - PRIMARY PARTITION 2
  - EXTENDED PARTITION
    - LOGICAL PARTITION 1
    - LOGICAL PARTITION 2
SECTORS -> CLUSTERS -> TRACKS -> CYLINDERS -> PARTITIONS -> FILE SYSTEM -> DIRECTORIES -> FILES.
========================================

*BOOTING PROCESS - LINUX BOOT PROCESS
[BIOS/UEFI INITIALIZATION]
WHEN THE COMPUTER IS TURNED ON THE BIOS (BASIC INPUT/OUTPUT SYSTEM) OR UEFI (UNIFIED EXTENSIBLE FIRMWARE INTERFACE) INITIALIZES THE HARDWARE.
EXAMPLE: THE BIOS PERFORMS POST (POWER ON SELF TEST) TO CHECK THE HARDWARE COMPONENTS.
[BOOTLOADER STAGE]
THE BIOS/UEFI LOOKS FOR A BOOTLOADER ON THE STORAGE DEVICE (LIKE GRUB - GRAND UNIFIED BOOTLOADER).
EXAMPLE: GRUB IS LOADED FROM THE MASTER BOOT RECORD (MBR).
[KERNEL LOADING]
THE BOOTLOADER LOADS THE LINUX KERNEL INTO MEMORY.
EXAMPLE: GRUB LOADS THE KERNEL FILE (EG "/boot/vmlinuz-linux").
========================================

#
$
*BOOTING PROCESS - LINUX INIT SYSTEM AND TARGETS
[INIT SYSTEM]
THE KERNEL STARTS THE INITIAL PROCESS ("INIT" OR "SYSTEMD") WHICH MANAGES SYSTEM INITIALIZATION.
EXAMPLE: SYSTEMD STARTS AND MANAGES THE SYSTEM SERVICES.
[TARGETS]
THE SYSTEM ENTERS A SPECIFIC TARGET WHICH DEFINES THE STATE OF THE MACHINE.
EXAMPLE: THE SYSTEM ENTERS GRAPHICAL MODE FOR THE USER LOGIN SCREEN.
========================================

$
*BOOTING PROCESS - WINDOWS BOOT PROCESS (BIOS/UEFI INITIALIZATION)
THE COMPUTER'S BIOS OR UEFI INITIALIZES THE HARDWARE AND PERFORMS A POST.
EXAMPLE: THE BIOS CHECKS THE RAM AND OTHER COMPONENTS.
========================================

#
$
*BOOTING PROCESS - WINDOWS BOOT MANAGER, LOADER, KERNEL, SESSION MANAGER
[BOOT MANAGER]
THE BIOS/UEFI LOADS THE WINDOWS BOOT MANAGER (BOOTMGR.EXE).
EXAMPLE: BOOT MANAGER IS FOUND ON THE ACTIVE PARTITION.
[BOOT LOADER]
BOOT MANAGER LOADS THE WINDOWS OS LOADER (WINLOAD.EXE).
EXAMPLE: WINLOAD.EXE LOADS ESSENTIAL DRIVERS AND THE KERNEL (NTOSKRNL.EXE).
[KERNEL INITIALIZATION]
THE KERNEL INITIALIZES THE HAL (HARDWARE ABSTRACTION LAYER) AND CORE SYSTEM PROCESSES.
EXAMPLE: NTOSKRNL.EXE STARTS ESSENTIAL SERVICES AND DRIVERS.
[SESSION MANAGER]
THE SESSION MANAGER SUBSYSTEM (SMSS.EXE) INITIALIZES USER SESSIONS.
EXAMPLE: SMSS.EXE SETS UP THE SYSTEM ENVIRONMENT AND LOADS THE WINLOGON PROCESS.
========================================

#
$
*BOOTING PROCESS - WINDOWS WINLOGON AND MAC EFI INITIALIZATION
[WINLOGON AND EXPLORER]
THE WINLOGON PROCESS (WINLOGON.EXE) HANDLES USER LOGIN.
EXAMPLE: AFTER LOGIN "EXPLORER.EXE" IS STARTED, LAUNCHING THE WINDOWS DESKTOP ENVIRONMENT.
[MAC OS BOOT PROCESS - EFI INITIALIZATION]
THE MAC EFI (EXTENSIBLE FIRMWARE INTERFACE) INITIALIZES THE HARDWARE.
EXAMPLE: EFI PERFORMS A HARDWARE CHECK SIMILAR TO POST.
[BOOT.EFI]
EFI LOADS THE "BOOT.EFI" FILE, WHICH IS THE MAC BOOT LOADER.
EXAMPLE: BOOT.EFI IS LOCATED IN THE EFI SYSTEM PARTITION.
========================================

#
$
*BOOTING PROCESS - MAC OS KERNEL LOADING AND LAUNCHD
[KERNEL LOADING]
BOOT.EFI LOADS THE MACOS KERNEL (MACH-KERNEL).
EXAMPLE: MACH-KERNEL IS LOADED INTO MEMORY.
[LAUNCHD]
THE KERNEL STARTS THE LAUNCHD PROCESS WHICH MANAGES SYSTEM INITIALIZATION AND SERVICES.
EXAMPLE: LAUNCHD REPLACES THE OLDER "INIT" PROCESS.
[SYSTEM INITIALIZATION]
"LAUNCHD" INITIALIZES SYSTEM SERVICES AND STARTS THE LOGIN WINDOW.
EXAMPLE: "LAUNCHD" STARTS SERVICES LIKE THE WINDOW SERVER AND USER ENVIRONMENT.

*MALWARE ANALYSIS ON WINDOWS (VOLATILITY PLUGINS)
[You can use all plugins for analysis but I highlight some specific plugins for analysis]
-windows.pslist
You can find a suspicious exe file on the list.
-windows.malfind
This find malicious exe files.
-windows.dlllist | grep 421
Note: 421 is the virus file PID. This show info about specific PID.
-windows.handles | grep 421

*VAD ANALYSIS (VOLATILITY)
-windows.vadinfo
Lists the virtual address descriptor [VAD] information for each process.
-windows.vadwalk
Walks the VAD tree for each process.
-windows.vadyarascan
Scans the VAD using yara rules.
